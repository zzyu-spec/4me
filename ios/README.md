# 하루결 아이폰 위젯 — Xcode 프로젝트

맥북에서 Xcode로 설치하는 별도 위젯 앱의 초기 구현입니다. **아직 Xcode 빌드·서명·아이폰 설치를 검증하지 않았습니다.** GitHub Pages 업데이트만으로 아이폰의 위젯 목록에 추가되지는 않습니다.

## 맥북에서 시작하기

1. 맥북 App Store에서 **Xcode**를 설치하고 한 번 실행해 초기 설정을 완료합니다. Xcode가 요구하는 macOS 버전을 확인해 주세요.
2. 이 저장소를 맥북에 다운로드하거나 Git으로 받습니다. 폴더 구조를 그대로 유지하세요.
3. `ios/HarugyeolWidgets/HarugyeolWidgets.xcodeproj`를 엽니다.
4. Xcode → Settings → Accounts에서 본인 Apple 계정을 연결합니다. 비밀번호나 인증 키를 대화창이나 저장소에 보내지 마세요.
5. 프로젝트의 **HarugyeolWidgetApp**, **HarugyeolWidgetExtension** 두 타깃 → Signing & Capabilities에서 같은 Team을 선택합니다. `Config/Shared.xcconfig`의 `HARUGYEOL_BUNDLE_BASE`를 본인이 사용할 고유 식별자로 바꾸면 앱·확장·공유 그룹이 함께 바뀝니다.
6. 두 타깃에서 같은 **App Groups**(`group.<식별자>.widgets`)와 **Keychain Sharing**(`<식별자>.widgetauth`)이 서명 프로파일에 허용되어야 합니다. 자동 서명에 오류가 나오면 그 상태로 중단하고 오류 문구를 확인하세요. 무료 Personal Team에서는 필요한 App Groups 권한을 사용할 수 없습니다.
7. 아이폰을 맥북에 연결하고 신뢰·개발자 모드를 허용합니다. 실행 대상을 본인 아이폰으로 선택하고 ▶ Run을 누릅니다.
8. 설치된 **하루결 위젯** 앱에서 기존 하루결 이메일 계정으로 로그인합니다. 이메일 인증과 웹앱의 계정 동기화가 켜져 있어야 합니다. 홈 화면 웹앱의 로그인은 자동으로 전달되지 않습니다.
9. 홈 화면 길게 누르기 → 위젯 추가 → 하루결. 잠금 화면은 길게 누르기 → 사용자화 → 잠금 화면 → 위젯 추가 → 하루결에서 선택합니다. iOS 16 이상이 필요합니다.

Apple Developer Program은 일반적으로 연 US$99이며 지역별 가격이 다릅니다. 기존 유료 Firebase 요금제와는 별개입니다. 이 작업에서 가입·결제·App Store/TestFlight 배포·Firebase 설정 변경은 수행하지 않았습니다. 공유 기능의 서명 권한 때문에 유료 Apple 개발자 계정이 필요할 수 있으므로 가입 전에 계정 상태와 Xcode 오류를 확인하세요. 현재 프로젝트는 App Store 제출용 아이콘·심사 준비까지 완료한 배포본이 아닙니다.

## 표시와 동작

- 홈 화면: 소형·중형·대형. 오늘 일정, 남은 투두, 남은 습관 수와 일부 항목.
- 잠금 화면: 한 줄·원형·직사각형. 남은 투두 수 또는 간단한 항목.
- 완료·미진행·취소·이월·완료 카테고리 투두와 날짜 미배정 마감일 투두를 남은 투두에서 제외합니다.
- 기존 `harugyeol/functions/reminder-model.js`를 두 타깃에서 그대로 번들해 반복·날짜별 예외·습관 이력을 해석합니다.
- 항목을 누르면 위젯 앱이 검증된 고정 하루결 주소를 열고 기존 날짜·메뉴 이동 인자를 전달합니다. iOS에서 설치된 PWA 대신 Safari로 열릴 수 있습니다.
- iOS가 갱신 시각을 결정합니다. 15분 뒤 갱신을 요청하지만 정시·즉시 갱신을 보장하지 않습니다. 앱의 ‘지금 갱신’으로 새로 요청할 수 있습니다.
- 연결 실패 시 같은 계정·같은 세션·같은 날짜의 최대 6시간 이내 캐시만 ‘연결 대기’로 표시합니다. 자정에는 이전 날짜 수치를 숨기는 타임라인 항목을 제공합니다. 기기를 재시작한 뒤 최초 잠금 해제 전에는 보안 저장소에 접근할 수 없습니다.
- 시스템 잠금 화면 개인정보 설정을 존중하도록 `privacySensitive`를 적용합니다. iOS가 이미 표시한 위젯을 회수하는 시각까지 앱이 강제할 수는 없습니다.

## 데이터·보안·비용

- Firebase Auth REST로 **기존 사용자 계정**을 확인하고 Firestore의 본인 `users/{uid}/planner/current`만 GET으로 읽습니다. 기존 규칙(본인 uid·이메일 인증)을 우회하지 않습니다. 서버 기록·보안 규칙·사진 저장 방식은 변경하지 않습니다.
- 비밀번호는 저장하지 않습니다. 갱신 토큰만 기기 보안 저장소(Keychain, 최초 잠금 해제 이후 접근, 다른 기기로 이전 불가)에 저장합니다. 공유 파일에는 표시할 최소 텍스트·개수만 저장하고 인증 토큰·일기·사진은 넣지 않습니다.
- 로그아웃/계정 변경과 비동기 요청이 겹치면 세션 식별자와 프로세스 간 잠금으로 이전 요청의 토큰·캐시 재저장을 차단합니다. 서버가 401/403을 반환하면 연결을 해제하고 캐시를 표시하지 않습니다.
- 웹앱의 로컬 변경 사항은 계정 동기화가 완료된 후에만 위젯에 보입니다. 위젯의 연결 해제는 기존 웹앱 로그인과 기록을 지우지 않습니다.
- 번들 설정은 기존 **공개 웹 API 키·프로젝트 ID**뿐입니다. 서비스 계정·관리자 키·APNs 키는 필요하지 않습니다. 기존 API 키에 브라우저 전용 제한이 있다면 REST 호출이 거부될 수 있습니다. 실제 키 제한·계정 연결은 미검증이며 설정 변경은 별도 검토가 필요합니다.
- 새 서버·스케줄러·유료 리소스를 만들지 않습니다. 갱신마다 기존 Firestore 문서 읽기가 발생하므로 기존 Firebase 사용량에 합산됩니다. OS 갱신 횟수·설치 기기 수에 따라 달라지며 무료라고 보장하지 않습니다.

## 개발 검증

리눅스에서 실행:

```sh
python3 ios/generate-project.py --check
python3 ios/tests/project-check.py
node --test ios/tests/*.test.cjs
node --test scripts/build-site.test.mjs
```

맥북에서 서명 없이 시뮬레이터용 빌드 확인:

```sh
xcodebuild -project ios/HarugyeolWidgets/HarugyeolWidgets.xcodeproj \
  -scheme HarugyeolWidgets -sdk iphonesimulator -configuration Debug \
  CODE_SIGNING_ALLOWED=NO build
```

실제 계정 로그인, 위젯의 잠금 상태 갱신, 오프라인 복귀, 계정 전환, 항목 터치 이동, 자정·시간대 변경은 아이폰에서 별도로 확인해야 합니다. 이 환경에는 Xcode/Swift 및 아이폰이 없어 이 검사를 통과했다고 보고하지 않습니다.

프로젝트/설정 파일을 재생성하려면 `python3 ios/generate-project.py`를 실행합니다. 서명 Team은 Xcode에서 선택하며 개인 인증 정보는 커밋하지 마세요. `ios/`는 웹 빌드에 복사되지 않으므로 기존 사이트와 저장 형식은 그대로 유지됩니다.
