# 담록 — 전용 Firestore 연결과 자료 이전

담록은 **담아 기록하다**의 줄임말입니다.

- 사이트: https://zzyu-spec.github.io/4me/damrok/
- Firebase 프로젝트: `harugyeol-e7866`
- **담록의 정상 읽기·쓰기 대상: 이름 지정 데이터베이스 `damrok`**
- Authentication: 기존 프로젝트의 앱 이름 `harugyeol-harugyeol-e7866`과 이메일 인증 계정을 공유
- 연결: `damrok/account.mjs`에서 `initializeFirestore(app, options, 'damrok')`를 호출

`ledger/account.mjs`, `firebase-context.mjs`, 루트 `firebase.json`·`firestore.rules`, 하루결·아르닛·가계부 코드는 변경하지 않습니다. 기본 DB에 남은 담록 원본도 삭제하지 않습니다. 예외적으로 사용자가 **이전 서버 확인**을 누를 때만 `(default)`의 본인 담록 경로를 읽기 전용으로 확인합니다.

## 1. 전용 데이터베이스 확인 및 보안 규칙 게시

이 작업 연결에는 Firebase 관리자 인증이 없습니다. **실제 DB 생성 여부·기존 사용자 자료·규칙 게시·운영 서버의 동기화 성공은 이 문서의 코드 배포만으로 검증된 것이 아닙니다.**

1. [Firebase Console](https://console.firebase.google.com/project/harugyeol-e7866/firestore)에서 프로젝트 `harugyeol-e7866`을 엽니다.
2. **Firestore Database의 데이터베이스 선택기에서 `damrok`을 선택**합니다. 없다면 데이터베이스 ID를 정확히 `damrok`으로 지정하여 만듭니다. 프로젝트의 기존 운영 위치를 확인해 위치를 선택합니다.
3. 선택된 DB가 **`damrok`**인지 확인한 뒤 **규칙** 탭을 엽니다.
4. [`damrok/firestore.rules`](https://github.com/zzyu-spec/4me/blob/main/damrok/firestore.rules)의 전체 내용을 복사하고 **게시**합니다.
5. **`(default)`나 `arnit`의 규칙에 붙여넣지 마세요.** 담록 전용 규칙은 `damrok`에서만 본인 경로를 허용합니다. 다른 서비스의 기존 규칙은 그대로 둡니다.
6. 담록에서 기존 계정으로 로그인하고 **다시 동기화**를 누릅니다. 서버 확인이 성공해야 **계정에 저장됨**이 표시됩니다.

이미 Firebase CLI 관리자 인증이 연결돼 있다면 저장소 루트에서 다음 두 명령으로 **담록 전용 구성만** 게시할 수 있습니다.

```sh
cd damrok
firebase deploy --only firestore:rules --project harugyeol-e7866 --config firebase.json
```

`damrok/firebase.json`은 `database: "damrok"`만 선언합니다. 루트 구성으로 전체 배포하거나 기본 DB 규칙을 수정할 필요가 없습니다.

## 2. 경로와 접근 범위

`damrok` DB 내부에서 기존 경로를 유지합니다.

- 자료: `/users/{uid}/damrokEntries/{id}`
- 사진·파일 원본 정보: `/users/{uid}/damrokAssets/{sha256}`
- 분할 원본: `/users/{uid}/damrokAssets/{sha256}/chunks/{index}`

이메일 인증을 마친 본인의 UID에만 읽기·쓰기를 허용합니다. 비로그인·미인증 이메일·다른 UID·다른 컬렉션 접근은 차단합니다. revision 트랜잭션으로 동시 수정을 감지하며 자료와 파일의 영구 삭제는 허용하지 않습니다.

비밀번호는 Firebase Authentication SDK로만 전달합니다. 담록 기록의 저장 필드에 비밀번호·로그인 토큰을 추가하지 않습니다. 사이트 계정 비밀번호를 평문으로 저장하는 기능은 제공하지 않습니다.

## 3. 기존 자료 확인과 손실 없는 이전

이전을 시작하기 전에 기존 버전의 다른 탭에서 편집을 멈추고 원본 백업을 보관하세요. 실제 자료 유무는 본인 계정으로 사이트에 로그인해서 확인합니다. 접근 실패를 ‘자료 0건’으로 표시하지 않습니다.

### 기존 기기 자료

- 이전 IndexedDB: `damrok-archive-account-<uid>`
- 새 전용 IndexedDB: `damrok-archive-account-<uid>-db-damrok`

새 저장소를 따로 사용하므로 `(default)`의 revision을 `damrok`에 잘못 재사용하지 않습니다. 이전 저장소는 읽기 전용으로 확인하고 **삭제하거나 초기화하지 않습니다.** 새 DB를 열 때 이전 계정 저장소를 자동으로 덮어쓰지 않습니다.

1. 로그인 후 오른쪽의 **이전 자료 확인 · 가져오기**를 누릅니다. 기기에 자료가 발견되면 버튼에 건수가 표시됩니다.
2. **기기 자료 백업 · 가져오기**를 누릅니다. 사진과 파일을 포함한 원본 JSON 백업을 먼저 내려받습니다.
3. 확인 창에서 복사를 승인합니다. 새 전용 기기 저장소에 복사하고 `damrok` 계정 동기화를 요청합니다.

### `(default)` 서버의 기존 담록 자료

1. 이전 도구에서 **이전 서버 확인**을 누릅니다. `(default)`에서 `/users/<현재 UID>/damrokEntries`만 조회합니다. 다른 서비스 자료는 조회하지 않습니다.
2. 권한 오류가 나오면 원본 자료가 없는 것이 아닙니다. 기존 `(default)`의 담록 읽기 권한이 있는 계정인지 확인하세요. 기존 DB 규칙을 이 작업에서 변경하지 않습니다. 이전 버전 사이트·이전 기기에서 전체 백업을 내보내 새 담록으로 가져오는 방법도 가능합니다.
3. **서버 원본 백업 · 가져오기**를 누르면 해당 자료가 참조하는 본인 `damrokAssets`만 읽습니다. 각 사진·파일은 분할 개수·길이·SHA-256을 검증합니다. 검증 실패 시 가져오기를 중단합니다.
4. 검증한 원본을 JSON 백업으로 내려받은 뒤 새 보관함으로 복사합니다. `(default)`에는 쓰거나 삭제하지 않습니다.

### 같은 ID가 있을 때

- 내용이 같으면 다시 복사하지 않습니다.
- 내용이 다르면 현재 자료를 덮어쓰지 않고 새 ID와 ‘(이전 자료)’ 이름으로 별도 보존합니다.
- 같은 원본을 다시 가져와도 동일한 사본이 계속 생성되지 않도록 안정된 복사 ID를 사용합니다.
- 복사 중 다른 탭이 같은 ID를 추가하면 원자적 저장을 중단해 덮어쓰기를 방지합니다.

### 이전 검증

1. **계정에 저장됨**을 확인합니다. 이 문구 전에 기기를 초기화하지 마세요.
2. 이전 도구의 **damrok 계정 자료 검증**을 누릅니다. 기기와 새 서버의 자료 수·revision·내용을 비교하고 모든 사진·파일 원본을 서버에서 다시 받아 SHA-256을 검증합니다.
3. 두 번째 브라우저에서 같은 계정으로 로그인해 같은 자료를 확인하고, 양쪽에서 편집 후 상대 기기에 반영되는지 확인합니다.
4. 다른 계정에서는 이 자료가 나타나지 않는지, 로그아웃하면 열린 자료·편집 내용·목록이 비워지는지 확인합니다.
5. **이전 검증 후에도 기존 자료는 자동 삭제하지 않습니다.** 원본 DB와 이전 기기 저장소, 백업을 유지합니다.

## 4. 동기화 상태

- **기기에 저장됨**: IndexedDB 저장 완료. 서버 확인 전입니다.
- **동기화 중**: `damrok` 서버와 자료·원본을 교환 중입니다.
- **계정에 저장됨**: 서버 조회/트랜잭션이 성공했고 남은 기기 변경이 없습니다.
- **동기화 실패**: 권한·연결·저장 또는 충돌 문제입니다. 기기 기록은 유지되며 안내를 확인하고 재시도할 수 있습니다.

로그인 전에는 계정 자료를 표시하지 않습니다. 로그아웃·계정 전환 시 열린 자료와 폼을 비우고 진행 중 작업의 UID·세대를 검증합니다. 기존 기기 자료를 삭제하는 로그아웃 방식은 사용하지 않습니다.

## 5. 디자인과 기능

참고 화면에 맞춘 아이보리·올리브 톤, 햇살·잎 그림자 배너, 왼쪽 공간 트리, 즐겨찾기, 최근 편집, 날짜 달력과 태그를 제공합니다. 페이지·링크·이미지·파일·공간, 기록 템플릿, 휴지통 복원과 전체 백업을 지원합니다. 예시 사용자 기록은 자동 생성하지 않습니다.

## 6. 기존 주소에서 자동 동기화·새 화면 적용

- 기존 주소 `/4me/damrok/`를 그대로 사용합니다. 처음 이 기능을 받는 기존 탭은 한 번 새로고침해야 합니다. 그 뒤에는 새 버전 링크를 따로 열 필요가 없습니다.
- 새 배포는 페이지가 보이는 동안 약 30초마다 확인하며, 탭 복귀·인터넷 재연결 때 바로 재확인합니다. 배포 버전과 HTML이 일치하는 경우에만 적용합니다.
- 편집 창·로그인 창 등 열린 창, 처리 중인 저장·동기화, 해결 전 충돌이 있으면 자동 새로고침을 보류합니다. 저장을 마치고 창을 닫으면 자동 적용합니다. 오프라인에서는 자동 새로고침하지 않습니다.
- 각 배포에서 내용 해시로 `damrok/releases/<hash>/` 파일과 `release.json`을 생성합니다. 화면과 모듈·스타일이 같은 버전을 사용하며, 공유 Firebase 파일도 새 버전 주소로 불러옵니다. 사용자 자료를 삭제하거나 브라우저 저장소를 초기화하지 않습니다.
- 데이터 변경은 기존 `damrok` 실시간 구독으로 감지합니다. 탭 복귀·연결 복구 때 재동기화하고, 페이지가 보일 때 45초 주기로 누락도 재확인합니다. 서버 권한과 연결이 정상이어야 기기 간 동기화됩니다.
- 열어둔 기록 보기에도 다른 기기 수정 사항이 반영됩니다. 편집 중인 폼의 입력은 바꾸지 않으며, 오래된 버전으로 저장하려 하면 기존 충돌 보호를 적용합니다.

자동 업데이트 검사를 재현하려면 저장소 루트에서:

```sh
node --test scripts/build-site.test.mjs damrok/tests/updates.test.mjs
```

실제 브라우저 두 개와 모형 Firebase를 사용하는 자동 반영 검사:

```sh
npm --prefix damrok/tests install
cd damrok/tests
npx playwright install chromium
npm run test:live
```

기존 계정/이전 브라우저 검사는 배포와 동일한 경로를 만들고 실행합니다.

```sh
node scripts/build-site.mjs
python3 -m http.server 4196 --bind 127.0.0.1 --directory _site
# 다른 터미널에서
npm --prefix damrok/tests test
```
