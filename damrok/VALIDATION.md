# 담록 변경 검증 결과

운영 Firebase와 로컬 모형 검사를 구분한 기록입니다. 실제 사용자 자료는 이 테스트의 입력으로 사용하지 않았습니다.

## 실행하여 통과한 검사

### 코드·변경 범위

- 정상 연결은 `damrok/account.mjs`의 `initializeFirestore(app, options, 'damrok')`를 사용합니다.
- `(default)` 연결은 명시적으로 실행하는 `damrok/migration.mjs`의 읽기 전용 이전 도구에서만 요청합니다.
- `ledger/account.mjs`, `firebase-context.mjs`, 루트 `firebase.json`·`firestore.rules` 및 다른 서비스 파일의 변경이 없음을 확인했습니다.
- 모듈 JavaScript 구문 검사와 Git 공백 오류 검사를 통과했습니다.

### 두 독립 브라우저 + 데이터베이스를 구분하는 모형 Firebase

실행 파일: `damrok/tests/named-db.cjs`, 모형 SDK: `damrok/tests/mock-sdk.mjs`.

- 일반 로그인·자료·사진 동기화의 모든 읽기·쓰기가 `damrok`을 사용하고, 일반 시작 시 `(default)` 읽기가 없음을 확인했습니다.
- UID별 기기 저장소와 모형 서버 경로가 분리됐습니다. 다른 UID·비로그인 요청은 모형 SDK에서 차단됐습니다.
- 두 번째 브라우저가 첫 번째 브라우저의 자료와 이미지 원본을 받고, 편집 후 반대 기기에 반영됨을 확인했습니다.
- 기존 기기 저장소는 변경되지 않았고, 기본 DB의 revision 9를 새 DB의 revision 1로 시작했습니다.
- 기본 DB의 자료·이미지를 읽어 새 DB로 복사한 뒤 원본 기기 자료·기본 DB 자료가 그대로임을 확인했습니다. 기본 DB 쓰기는 0회입니다.
- 같은 ID의 다른 내용은 별도 사본으로 보존했고, 동일 원본 재가져오기는 추가 사본을 생성하지 않았습니다.
- 새 모형 서버의 자료 수·revision·내용·사진 SHA-256을 다시 검증했습니다.
- 서버 권한 오류 시 기기 편집이 보존되고 ‘동기화 실패’를 표시했습니다. 권한 복구 후 재시도해 저장됐습니다.
- `기기에 저장됨`, `동기화 중`, `계정에 저장됨`, `동기화 실패`가 모두 실제 해당 단계에서 표시됐습니다.
- 이전 서버 확인 권한이 없을 때 ‘확인 실패’로 표시했으며 ‘자료 0건’으로 판정하지 않았습니다.
- 로그아웃 후 목록·열린 자료의 DOM·편집 내용이 비워졌고 모형 서버의 비로그인 읽기가 차단됐습니다. 다른 계정에는 기존 자료가 나타나지 않았습니다.
- 로그인 테스트용 비밀번호가 기록 문서에 저장되지 않았습니다.
- 브라우저 JavaScript 오류 0건입니다.

**이 결과는 모형 SDK와 모형 서버를 사용한 앱 동작 검사입니다. 배포된 Firestore 보안 규칙의 실제 접근 차단을 검증한 결과는 아닙니다.**

### 디자인·확장 기록 기능

별도 로컬 브라우저 검사에서 페이지·링크·이미지·파일·공간·템플릿 작성, 사진·파일 원본의 두 브라우저 왕복, 문자 그대로의 스크립트 표시, 즐겨찾기·검색·태그·휴지통·백업 복원과 320–1536px 레이아웃, 모바일 메뉴 숨김을 검사했습니다. 사용자의 예시 기록은 자동 생성하지 않습니다.

## 실행하지 못한 실제 검증

| 항목 | 상태와 이유 |
|---|---|
| 운영 `damrok` DB 생성·존재 확인 | Firebase 관리자 인증 연결 없음. 확인하지 못함 |
| `damrok` 규칙 게시 | 직접 실행하지 않음. 전용 파일과 수동 절차 제공 |
| 실제 기존 기기·`(default)` 자료 유무 | 실제 사용자 계정으로 접근하지 않음. 로그인 후 이전 도구에서 확인 필요 |
| 운영 DB로 실제 이전 완료 | 수행하지 않음. 원본 삭제 없음 |
| 운영 Firebase에서 두 브라우저 동기화·UID 차단 | 실행하지 못함. 규칙 게시 후 실제 계정으로 확인 필요 |
| Firestore 에뮬레이터에서 규칙 실행 | 에뮬레이터 JAR 다운로드 요청이 작업 환경의 네트워크 정책으로 HTTP 403 차단됨. 실행하지 못함 |

## 재현 방법: 모형 브라우저 검사

저장소 루트에서 정적 서버를 실행합니다.

```sh
python3 -m http.server 4196 --bind 127.0.0.1
```

다른 터미널에서:

```sh
npm --prefix damrok/tests install
cd damrok/tests
npx playwright install chromium
npm test
```

시스템 Chromium을 사용할 경우:

```sh
CHROMIUM_BIN=/usr/bin/chromium npm test
```

기본 URL은 `http://127.0.0.1:4196/damrok/`이며 `DAMROK_TEST_URL`로 바꿀 수 있습니다. 이 검사에서는 Firebase SDK 요청을 로컬 모형으로 교체하므로 운영 사용자·데이터·규칙을 변경하지 않습니다.

## 실제 운영 검증 절차

[SETUP.md](SETUP.md)의 전용 규칙 게시, 원본 백업과 이전, 두 번째 브라우저 확인 절차를 따릅니다. 사이트의 **damrok 계정 자료 검증**이 성공하기 전에는 실제 이전 완료로 간주하지 않습니다. 이전 검증 뒤에도 기존 원본은 자동 삭제하지 않습니다.
