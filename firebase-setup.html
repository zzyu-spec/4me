# 하루결 로그인·동기화 연결

현재 `firebase-config.json`은 비어 있으므로 공개 사이트에서 실제 회원가입·동기화는 아직 활성화되지 않습니다. 기존 기기 저장은 계속 동작합니다. 아래 과정은 프로젝트 소유자가 한 번만 진행합니다.

1. [Firebase Console](https://console.firebase.google.com/)에 Google 계정으로 로그인하고 **프로젝트 만들기**를 선택합니다. 처음에는 Google Analytics 없이 시작해도 됩니다. **Spark(무료)**를 유지하고 결제 계정/카드를 연결하지 않습니다. 현재 무료 한도는 Firebase 공식 콘솔에서 확인하세요.
2. **프로젝트 설정 → 일반 → 앱 추가 → 웹(</>)**에서 하루결 웹 앱을 등록합니다. Firebase Hosting은 필요하지 않습니다. 사이트는 기존 GitHub Pages를 계속 사용합니다.
3. 표시되는 `firebaseConfig`의 `apiKey`, `authDomain`, `projectId`, `appId`를 복사합니다. 이 웹 설정은 공개용입니다. **서비스 계정 JSON·private_key·관리자 비밀 키는 앱이나 GitHub에 넣지 마세요.**
4. **Authentication → Sign-in method**에서 **이메일/비밀번호**를 활성화합니다. **Settings → Authorized domains**에 `zzyu-spec.github.io`를 추가합니다. 가입 확인 메일의 발신 이름도 확인하세요.
5. **Firestore Database → 데이터베이스 만들기**에서 기본 `(default)` 데이터베이스를 생성합니다. 리전은 실제 사용할 지역에 가까운 곳으로 정하고, **프로덕션 모드**로 시작합니다. 지역은 생성 후 바꾸기 어려우니 확인하세요.
6. **Firestore → Rules**에 저장소의 [`firestore.rules`](./firestore.rules) 전체를 붙여 넣고 **Publish**합니다. 다른 사용자의 기록과 로그인하지 않은 요청은 차단되며, 이메일 확인을 마친 사용자만 자기 기록을 읽고 쓸 수 있습니다. 모든 사용자에게 읽기/쓰기를 허용하는 테스트 규칙을 쓰지 않습니다.
7. 먼저 하루결 **설정 → 로그인·동기화 → Firebase 연결 설정**에 웹 설정을 붙여 넣고 저장합니다. **회원가입 → 이메일 확인 → 로그인 → 현재 기록으로 동기화 시작** 순서로 시험합니다. 기존 기록이 있는 기기에서는 먼저 JSON 백업을 받아 두세요.
8. 두 기기 모두 자동으로 같은 프로젝트를 쓰도록 하려면 `firebase-config.json`에 공개용 네 항목을 저장하고 GitHub Pages에 배포합니다. 이 파일은 비밀번호나 서버 관리자 키가 아닙니다. 프로젝트를 만든 뒤 공개용 웹 설정만 이 대화로 알려주면 적용 작업을 이어갈 수 있습니다. 프로젝트를 공개해도 Firestore 규칙을 느슨하게 바꾸면 안 됩니다.

```json
{
  "apiKey": "Firebase가 제공한 공개용 웹 API 키",
  "authDomain": "프로젝트ID.firebaseapp.com",
  "projectId": "프로젝트ID",
  "appId": "Firebase가 제공한 웹 앱 ID"
}
```

## 동작과 제한

- 로그인 없이도 기존 localStorage 저장과 JSON 백업을 사용할 수 있습니다.
- 로그인만으로 기존 기록을 서버에 올리지 않습니다. 사용자가 동기화 시작을 선택해야 합니다.
- 로컬 기록은 오프라인에서도 저장됩니다. 인터넷이 복구되면 다시 동기화합니다. Firestore의 브라우저 영구 캐시도 활성화하지만, 충돌 검사를 위한 서버 트랜잭션은 온라인에서만 수행합니다.
- 두 기기에서 따로 수정한 전체 기록이 충돌하면 조용히 덮어쓰지 않고 자동 동기화를 멈춥니다. 양쪽을 기기 안전 백업한 뒤 어느 기록을 사용할지 선택합니다. 현재 버전은 항목별 자동 병합이 아닌 전체 기록 버전 비교 방식입니다.
- **사진 기능은 유지하지만 사진은 동기화하지 않습니다.** 기존 일기·식사 사진은 해당 기기에 남습니다. 다른 기기의 텍스트를 받을 때 해당 날짜에 이미 있는 기기 사진은 보존합니다. 사진을 옮기려면 기존 JSON 백업/불러오기를 사용하세요.
- 기기 안전 백업은 IndexedDB에 최근 10개를 보관하며 사진을 포함합니다. 서버 백업은 이전 텍스트 버전을 보관하고 주기적으로 최근 10개로 정리합니다. 서버 백업은 사진을 포함하지 않으며 무료 요금제의 관리형 데이터베이스 백업 서비스와는 다릅니다.
- Firestore 문서 크기 제한 때문에 사진을 제외한 기록 800KB까지 동기화하도록 보호 장치를 두었습니다. 초과하면 동기화를 멈추고 기기 기록을 보존합니다. 데이터가 커지면 항목별 문서 구조로 확장해야 합니다.
- 로그아웃해도 기기 기록은 남습니다. 공유 기기에서는 JSON 백업 후 브라우저 저장소 관리에 주의하세요. 다른 탭에서 기록이 바뀌면 동기화를 멈춰 오래 열린 탭이 덮어쓰지 않게 합니다.
- 원격 서비스 연결과 실제 보안 규칙은 소유자의 Firebase 프로젝트에서 최종 확인해야 합니다. 프로젝트 미생성 상태에서는 실제 로그인·동기화가 완료됐다고 볼 수 없습니다.

## SDK 재생성

Firebase Web SDK 11.10.0을 고정하여 로컬 `firebase-vendor.js`로 번들했습니다. 일상 실행에는 npm이나 외부 CDN이 필요 없습니다. `tools/firebase-entry.js`가 번들 진입점이고 SDK 저작권 고지는 `firebase-vendor.js.LEGAL.txt`에 있습니다. 재생성은 별도 임시 디렉터리에 `firebase@11.10.0`과 `esbuild`를 설치한 뒤 진입점을 복사해 esbuild의 `--bundle --minify --format=esm --target=es2020 --legal-comments=external` 옵션으로 수행합니다. 종속성의 서명·체크섬 검증을 우회하지 않습니다.
