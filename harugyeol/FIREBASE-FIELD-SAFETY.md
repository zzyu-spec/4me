# Firebase 필드명 오류 수정

## 원인과 수정 위치

- `index.html`의 `todoSectionForm(old)` 기본 카테고리 편집 분기에서 `state.sectionColors['']=color`를 만들었다. 기본 카테고리는 내부 식별자가 빈 문자열이므로 정상적인 UI 조작으로도 Firestore가 허용하지 않는 필드명이 생겼다.
- 같은 파일의 `data-section-color` 변경 처리와 기존 카테고리 이름 변경 처리도 객체 키에 직접 기록했다. 신규 카테고리 이름은 trim/빈 이름 검사가 있었지만 기본 식별자에는 적용되지 않았다.
- `cloud.js`의 `snapshot()`은 로컬 객체를 복제하고 사진만 제외했으며, `rpc()`의 `Transaction.set()`은 필드명을 검증하지 않고 그 객체를 그대로 전송했다. `migrate()`/JSON 복원도 기존 sectionColors 키를 유지하므로 예전 빈 키가 반복해서 전송됐다.
- 이제 `setTodoSectionColor()`를 통해 기본 카테고리 색상은 `todoDefaultSectionColor`라는 단일 설정 필드에 기록한다. 일반 카테고리는 빈 이름/공백 이름을 기록하지 않는다. `sectionColor()`는 새 설정을 우선 읽고, 기존 빈 키의 색상도 이전처럼 읽는다. 이전 키를 지우거나 사용자 색상을 초기화하지 않는다.

## 기존 기록 보존 및 전송 검증

`cloud.js`의 `cloudFields()`는 **전송용 복제본만** 재귀적으로 처리한다. sectionColors뿐 아니라 routineOrder, 감정 설정, 사용자 정의 확장 필드, 배열 속 기록 객체와 서버의 이전 버전 백업에도 적용된다.

- 빈 키, 공백만 있는 키, Firestore 예약형 `__…__` 키는 `~harugyeol-key~` + UTF-8 16진수로 변환한다. 원래 이 접두사로 시작하는 키도 변환해 충돌을 방지한다.
- 정상 키(한국어, 점을 포함한 이름 등)와 값은 유지한다. 필드를 버리거나 이름을 trim해서 합치지 않는다.
- 서버 문서/백업의 snapshot 안에 전송 형식 표시 `~harugyeol-key~version:1`을 함께 저장한다. 이 키와 같은 이름의 원본 필드도 먼저 인코딩하므로 충돌하지 않는다. `decodeCloudDocument()`가 읽기·충돌 처리·다른 기기로 복원·서버 백업 다운로드 시 원래 키를 복원한다. 버전 표시가 없는 기존 문서는 그대로 읽는다.
- localStorage/state/기기 안전 백업/JSON 내보내기는 원래 키와 모든 원본 값을 유지한다. 사진과 대표사진은 기존처럼 기기에 유지하며 전송하지 않는다.
- 변환 후 필드명 1500바이트 초과, 중첩 깊이 초과, 중첩 배열 등 변환만으로 해결할 수 없는 데이터는 쓰기 전에 중단한다. 문제 객체 경로와 사유를 계정·동기화 상태에 표시한다. 값을 임의로 삭제해 통과시키지 않는다.
- 전송 후에만 동기화 버전/기준 해시를 갱신한다. 네트워크 실패/검증 실패는 로컬 기록을 바꾸지 않으며 기존 ‘지금 동기화’ 또는 자동 재시도로 다시 시도할 수 있다. 인코딩은 결정적이므로 같은 오류로 무한히 새 버전을 업로드하지 않는다.

모든 기기에서 새 버전으로 업데이트한 뒤 동기화한다. 이전 앱은 새 전송용 필드명 인코딩을 해석하지 못한다. 서비스 워커 캐시 버전은 v168로 올렸다. 문서 최상위 필드는 기존 revision/snapshot/updated_at 또는 created_at 그대로 유지하므로 저장소에 있는 Firestore 보안 규칙의 변경이 필요 없다.

## 검증

`tools/cloud-field-validation.test.cjs`는 별도 테스트 계정 모형/엄격한 필드명 검증 SDK로 다음을 확인한다.

- 기존 빈 키·공백 키·예약 키·접두사 충돌·다른 객체의 빈 키 및 중첩 기록의 보존
- 기본 카테고리 실제 수정 폼의 새 필드 저장 및 기존 색상 보존
- 통신 실패 시 localStorage 바이트/동기화 버전 불변, 재시도 성공
- 과도한 필드명 길이의 경로/사유 표시, 전송 차단, 로컬 보존 및 수정 후 재시도
- 다른 기기의 키 복원, 기존 정상 색상/설정/메모/일정/루틴 보존, 서버 버전 백업
- JSON 내보내기의 원본 키·사진 보존

`tools/login-entry.test.cjs`로 기존 로그인/오프라인/자동 동기화/사진 제외/JSON 사진 백업/계정 격리/충돌/인증 만료를 확인한다. 실사용자 Firebase 계정/문서에는 테스트 쓰기를 하지 않는다. 실제 운영 서버 통신은 이 테스트 범위 밖이다.
