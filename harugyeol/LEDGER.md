# 별도 가계부

주소: `/4me/ledger/`. 위플의 빠른 입력/종류·수단별 조회 흐름을 참고하며 화면·브랜드·에셋은 복제하지 않았다.

- 수입/지출/이체, 날짜/금액/카테고리/결제수단/메모, 수정/삭제(서버 tombstone), 월별 내역/달력/카테고리 지출 분석, 제목·메모 검색, 같은 계정 JSON 백업 내보내기/없는 내역만 가져오기.
- 월 합계는 조회 월 전체 기준, 목록과 분석은 선택 필터 기준. 이체는 수입/지출에서 제외. 결제수단은 사용자 입력값으로 분류하며 실제 은행 연동·잔액·카드대금 자동 정산은 없다.
- 기존 Firebase 프로젝트·동일 Auth 앱 이름 사용. 같은 브라우저의 하루결 로그인 재사용. 별도 호스트로 옮기면 재로그인이 필요하다. 인증된 동일 uid를 사용하지만 일기·플래너 문서는 수정하지 않는다.
- 계정별 localStorage `harugyeol-ledger-v1:{uid}`: version/items/pending/backups. 금액은 양의 정수 원. 저장실패 시 메모리 상태 미변경. 다른 탭 변경 시 쓰기 중단. 큐는 새로고침·네트워크 장애 뒤 유지. 로그아웃 시 읽기·동기화 중지, 기록 삭제 없음.
- Firestore 기본 DB `/users/{uid}/ledgerEntries/{entryId}`. revision 비교 트랜잭션, 기기별 미전송 큐. 충돌 내역은 자동 덮어쓰지 않고 선택 시 변경 전 기기 데이터를 최대 5개 보관. 백업에 포함. 빈 필드명이나 사용자 문자열을 동적 문서 키로 사용하지 않는다.
- 일기 `오늘의 소비`: 해당 날짜 지출만 실시간 읽기. 수입·이체 제외, 최대5건/+N/합계. 지출을 일기에 복사하지 않아 중복 계산 없음. 기존 `journals[date].spending` 텍스트 보존. 계정 미연결·권한 실패 안내. 기존 플래너 JSON/사진/백업 형식 변경 없음.

## 서버 적용

새 경로를 허용하는 `firestore.rules` 추가분은 실제 배포가 필요하다. 기존 규칙 블록과 catch-all은 보존했다. 기존 프로젝트에 배포할 때는 현재 운영 규칙에 별도 변경이 없는지 확인 후 병합한다.

본인 Google Cloud Shell의 같은 저장소에서:

```sh
git pull --ff-only
npm exec --yes --package=firebase-tools@15.35.0 -- firebase deploy --only firestore:rules --project harugyeol-e7866 --non-interactive
```

이 명령은 새 데이터베이스나 함수를 생성하지 않는다. Firestore 읽기·쓰기에는 사용량 요금이 적용될 수 있다. 운영 규칙 변경 권한/ADC 필요. 인증정보는 채팅·저장소에 넣지 않는다. Codex에서 실제 계정 동기화·운영 보안 규칙·아이폰 실기기 수신은 검증하지 않았다.

## 업데이트 내역 운영

사용자에게 보이는 변경을 배포할 때 `release-notes.js`의 `release.id`와 `notes`를 함께 갱신하고 SW 캐시 버전을 올린다. 실제 사용 가능 상태와 서버 준비 상태를 구분해 적는다. 하루결에서는 새 업데이트를 한 번 안내하고 설정에서 다시 열 수 있다. 사용자 지시에 따라 가계부의 업데이트 팝업과 업데이트 버튼은 제거했다. 사용자가 명시적으로 다시 요청할 때까지 가계부에는 업데이트 팝업을 추가하거나 자동 표시하지 않는다.

## 카테고리 및 이체 입력 변경

- 계정별 기존 v1 파일에 선택 필드 `categories`, `categoryPending`을 추가한다. 오래된 백업에 없어도 기본 수입/지출 목록을 제공한다. 내역의 `category` 문자열은 변환·삭제하지 않는다.
- 수입/지출별 카테고리 관리에서 추가/선택 목록 제외를 지원한다. 같은 종류의 중복·공백 이름을 차단한다. 동일 이름을 수입과 지출에 각각 만들 수 있다. 기본 카테고리 제외도 tombstone으로 저장하고 과거 내역은 유지한다.
- 서버 경로 `/users/{uid}/ledgerCategories/{id}`에 별도 revision 트랜잭션/오프라인 큐/충돌 선택/변경 전 백업을 적용한다. JSON 내보내기/가져오기에 카테고리가 포함된다. 새 보안 규칙 배포가 필요하다.
- 이체 받을 수단 입력칸은 제거했다. 이전 내역의 `toPayment`는 편집해도 보존하고 새 이체는 빈 문자열로 저장한다. 금액 집계는 이전과 같이 수입·지출에서 이체를 제외한다. 기존 서버 규칙의 비어 있지 않은 `toPayment` 조건을 제거하므로 새 규칙 배포가 필요하다. 다른 일정/일기/푸시 규칙은 변경하지 않는다.

## 백업 UI 제거

사용자 요청에 따라 가계부의 백업 다운로드/가져오기 버튼과 관련 안내·사용하지 않는 처리 코드를 제거했다. 명시적인 저장 후 기기 저장·계정 자동 동기화, 실패 시 재시도, 내부 충돌 복구 기록 및 기존 v1 데이터 형식은 유지한다. 입력 중 자동 저장으로 변경한 것은 아니다. 하루결의 백업 기능은 변경하지 않는다.

## 일기 연결 초기화 오류 수정

일기의 연결 실패를 실제 번들 SDK로 재현했다. 이미 시작한 Firestore에 새 persistentLocalCache 인스턴스를 넘겨 다시 initializeFirestore하면 failed-precondition이 발생한다. firebase-context.mjs에서 Firebase App 객체별 기본 Firestore 인스턴스를 공유하고 cloud.js와 ledger/account.mjs 모두 이 경로를 사용한다. 기존 캐시·인증·데이터·보안 규칙은 변경하지 않는다. 연결 실패 시 오류 원인과 코드도 표시한다.

`node tools/ledger-shared-firebase.test.cjs`: 실제 Firebase SDK에서 이전 오류 재현 및 하루결 먼저/가계부 먼저 두 초기화 순서의 인스턴스 공유 확인. 외부 요청을 차단한 검사이며 운영 계정 로그인·서버 권한 검증을 대신하지 않는다. 가계부 업데이트 팝업 비활성화 지시는 유지한다.

## 오늘의 소비 모바일 레이아웃 / 배포 경로 수정

- 일기 소비 창을 가계부 합계·내역, 별도 버튼 행, 소비 메모, 완료 영역으로 분리했다. 연결 오류는 일반 크기 문단으로 표시하고 버튼은 flex 줄바꿈과 44px 터치 영역을 사용한다. 메모 입력과 내부 저장 데이터는 유지한다.
- `ledger/account.mjs` 설정 요청을 `new URL('../firebase-config.json', import.meta.url)`로 고정했다. 이전 fetch 문자열은 일기 `/4me/`에서 `/firebase-config.json`으로 해석되어 운영 배포 경로에서 404가 날 수 있었다. 모듈 기준으로 `/4me/firebase-config.json`을 요청한다.
- `tools/journal-spending-layout.test.cjs`: `/4me/` 접두 경로를 실제로 구성해 정상/설정 파일 실패/권한 실패, 라이트/다크, 320×568·390·588px에서 경계·순서·메모 보존을 확인한다. SDK와 서버 응답은 모형이며 iPhone 실기기 및 실제 사용자 계정은 별도 검증 대상이다.

## 새 기록 입력창 압축

종류/날짜 및 카테고리/결제수단을 각각 2열로 배치하고 금액/내역은 전체 너비로 유지했다. 카테고리 관리 버튼은 카테고리 제목 옆으로 이동했다. 빈 메모는 접고 기존 메모가 있으면 펼친다. date 입력에 명시적 width/max-width/min-inline-size/height와 WebKit 표시 정렬을 적용해 iOS의 기본 날짜 컨트롤이 칸 밖으로 넘치는 것을 방지한다. 입력명·저장 데이터·수입/지출 구분·기존 이체 정보는 변경하지 않는다.

`tools/ledger-editor-layout.test.cjs`: 320–588px 라이트/다크에서 두 열 정렬과 날짜 경계, 작성 중 카테고리 추가 시 입력 유지, 저장/재열람/메모 보존을 검사한다. Chromium 검사이며 실제 iPhone Safari는 별도 검증 대상이다. 가계부 업데이트 팝업은 계속 비활성화한다.
