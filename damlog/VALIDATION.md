# 담록 변경 검증 결과

운영 Firebase와 로컬 모형 검사를 구분한 기록입니다. 실제 사용자 자료는 이 테스트의 입력으로 사용하지 않았습니다.

## 실행하여 통과한 검사

### 코드·변경 범위

- 정상 연결은 `damlog/account.mjs`의 `initializeFirestore(app, options, 'damlog')`를 사용합니다.
- `(default)` 연결은 명시적으로 실행하는 `damlog/migration.mjs`의 읽기 전용 이전 도구에서만 요청합니다.
- `ledger/account.mjs`, `firebase-context.mjs`, 루트 `firebase.json`·`firestore.rules` 및 다른 서비스 파일의 변경이 없음을 확인했습니다.
- 모듈 JavaScript 구문 검사와 Git 공백 오류 검사를 통과했습니다.

### 두 독립 브라우저 + 데이터베이스를 구분하는 모형 Firebase

실행 파일: `damlog/tests/named-db.cjs`, 모형 SDK: `damlog/tests/mock-sdk.mjs`.

- 일반 로그인·자료·사진 동기화의 모든 읽기·쓰기가 `damrok`을 사용하고, 일반 시작 시 `(default)` 읽기가 없음을 확인했습니다.
- UID별 기기 저장소와 모형 서버 경로가 분리됐습니다. 다른 UID·비로그인 요청은 모형 SDK에서 차단됐습니다.
- 두 번째 브라우저가 첫 번째 브라우저의 자료와 이미지 원본을 받고, 편집 후 반대 기기에 반영됨을 확인했습니다.
- 기존 기기 저장소는 변경되지 않았고, 기본 DB의 revision 9를 새 DB의 revision 1로 시작했습니다.
- 기본 DB의 자료·이미지를 읽어 새 DB로 복사한 뒤 원본 기기 자료·기본 DB 자료가 그대로임을 확인했습니다. 기본 DB 쓰기는 0회입니다.
- 같은 ID의 다른 내용은 별도 사본으로 보존했고, 동일 원본 재가져오기는 추가 사본을 생성하지 않았습니다.
- 새 모형 서버의 자료 수·revision·내용·사진 SHA-256을 다시 검증했습니다.
- 서버 권한 오류 시 기기 편집이 보존되고 ‘동기화 실패’를 표시했습니다. 권한 복구 후 재시도해 저장됐습니다.
- `기기에 저장됨`, `동기화 중`, `계정에 저장됨`, `동기화 실패`가 모두 실제 해당 단계에서 표시됐습니다.
- 이전 서버 확인 권한이 없을 때 ‘확인 실패’로 표시했으며 ‘자료 0건’으로 판정하지 않았습니다.
- 로그아웃 후 목록·열린 자료의 DOM·편집 내용이 비워졌고 모형 서버의 비로그인 읽기가 차단됐습니다. 다른 계정에는 기존 자료가 나타나지 않았습니다.
- 로그인 테스트용 비밀번호가 기록 문서에 저장되지 않았습니다.
- 브라우저 JavaScript 오류 0건입니다.

**이 결과는 모형 SDK와 모형 서버를 사용한 앱 동작 검사입니다. 배포된 Firestore 보안 규칙의 실제 접근 차단을 검증한 결과는 아닙니다.**

### 디자인·확장 기록 기능

별도 로컬 브라우저 검사에서 페이지·링크·이미지·파일·공간·템플릿 작성, 사진·파일 원본의 두 브라우저 왕복, 문자 그대로의 스크립트 표시, 즐겨찾기·검색·태그·휴지통·백업 복원과 320–1536px 레이아웃, 모바일 메뉴 숨김을 검사했습니다. 사용자의 예시 기록은 자동 생성하지 않습니다.

## 실행하지 못한 실제 검증

| 항목 | 상태와 이유 |
|---|---|
| 운영 `damrok` DB 생성·존재 확인 | Firebase 관리자 인증 연결 없음. 확인하지 못함 |
| `damrok` 규칙 게시 | 직접 실행하지 않음. 전용 파일과 수동 절차 제공 |
| 실제 기존 기기·`(default)` 자료 유무 | 실제 사용자 계정으로 접근하지 않음. 로그인 후 이전 도구에서 확인 필요 |
| 운영 DB로 실제 이전 완료 | 수행하지 않음. 원본 삭제 없음 |
| 운영 Firebase에서 두 브라우저 동기화·UID 차단 | 실행하지 못함. 규칙 게시 후 실제 계정으로 확인 필요 |
| Firestore 에뮬레이터에서 규칙 실행 | 에뮬레이터 JAR 다운로드 요청이 작업 환경의 네트워크 정책으로 HTTP 403 차단됨. 실행하지 못함 |

## 재현 방법: 모형 브라우저 검사

저장소 루트에서 정적 서버를 실행합니다.

```sh
python3 -m http.server 4196 --bind 127.0.0.1
```

다른 터미널에서:

```sh
npm --prefix damrok/tests install
cd damrok/tests
npx playwright install chromium
npm test
```

시스템 Chromium을 사용할 경우:

```sh
CHROMIUM_BIN=/usr/bin/chromium npm test
```

기본 URL은 `http://127.0.0.1:4196/damrok/`이며 `DAMROK_TEST_URL`로 바꿀 수 있습니다. 이 검사에서는 Firebase SDK 요청을 로컬 모형으로 교체하므로 운영 사용자·데이터·규칙을 변경하지 않습니다.

## 실제 운영 검증 절차

[SETUP.md](SETUP.md)의 전용 규칙 게시, 원본 백업과 이전, 두 번째 브라우저 확인 절차를 따릅니다. 사이트의 **damrok 계정 자료 검증**이 성공하기 전에는 실제 이전 완료로 간주하지 않습니다. 이전 검증 뒤에도 기존 원본은 자동 삭제하지 않습니다.


## 자동 반영 변경 검증

- 빌드·업데이트 검사 6개 통과: 새 배포 감지, 편집/저장 중 보류, 중복 새로고침 방지, 오프라인/실패 시 유지, HTML 준비 대기, 앱/공유 파일 변경 시 자동 버전 생성과 기존 서비스 공개 경로 보존.
- `damlog/tests/live-updates.cjs` 실제 브라우저 + 모형 Firebase 검사 통과: 수동 동기화 없이 5초 내 다른 브라우저 기록·열린 보기 갱신, 기존 주소에서 배포 감지, 작성 중 입력 보존, 저장 후 한 번 자동 새로고침, 원래 주소 복구, 새 버전에서 저장 내용 유지. JavaScript 오류 0건.
- 새 배포 경로에서 기존 `named-db.cjs` 계정 분리·이전·로그아웃 검사 통과.
- 배포용 기존 서비스 회귀 검사 27개 통과.
- 실시간 변경 이벤트는 검사에서 모형 Firebase 이벤트로 전달했습니다. 실제 운영 Firestore 규칙·서버 동기화가 새로 검증된 것은 아닙니다. 기존에 명시한 운영 검증 한계는 그대로입니다.

## 로그인 초기화 오류 수정 검증

- 원인: 버전 폴더 안의 모듈에서 `fetch('../../../firebase-config.json')`을 호출해 문서 주소 기준 `/firebase-config.json`을 요청했습니다. 운영 사이트의 실제 설정 경로 `/4me/firebase-config.json`과 달랐고, 실패한 초기화 뒤 SDK 없이 로그인 메서드가 실행됐습니다.
- 수정: `new URL('../firebase-config.json', import.meta.url)`로 모듈 기준 주소를 사용합니다. 인증 초기화를 단일 Promise로 기다리고, 준비 중에는 버튼을 비활성화하며 실패 후 재시도를 허용합니다. 공통 Firebase 연결과 Authentication 프로젝트·DB·보안 규칙은 변경하지 않습니다.
- `auth-ready.test.mjs` 통과: 초기화 전 로그인 대기, 초기화 중복 방지, 실패 후 재시도, 회원가입·로그아웃의 SDK 준비 보장.
- `auth-prefix.cjs` 통과: 실제 Firebase JavaScript SDK와 브라우저 저장소를 사용하고 운영과 같은 `/4me/` 하위 경로에서 검사했습니다. 올바른 설정 URL, 느린 초기화 중 버튼 차단, 실제 SDK 로그인 호출 도달, 일시적 설정 503 후 재시도, 열린 로그인 폼 유지, JavaScript 오류 0건을 확인했습니다.
- 외부 인증 API 응답은 모형으로 대체했습니다. 실제 사용자 계정 로그인·운영 Firestore 동기화 성공을 검사한 결과는 아닙니다. 실제 이메일·비밀번호를 테스트에 사용하지 않았습니다.


## 독립 페이지·글 추가로 개편

- 섹션 편집 UI를 제거했습니다. 부모 페이지에서 페이지/글을 각각 별도 문서로 추가하고 다시 열 수 있습니다. 이전 섹션 내용은 보존해 일반 내용으로 표시하며 비어 있는 틀은 표시하지 않습니다.
- `page-node.test.mjs`: 기존 본문/이전 내용 보존, 독립 부모 ID·글 형식·본문 왕복, 이름 변경에도 연결 유지, 잘못된 순환 관계에서 무한 반복 방지 검사 통과.
- `child-pages.cjs`: 운영과 같은 `/4me/` 경로의 두 브라우저 + 모형 Firebase에서 공간 > 부모 페이지 > 하위 페이지/글 > 더 안쪽 글, 독립 문서 저장과 부모 본문 불변, 열기/상위 돌아가기, 이름 변경, 자동 자식 목록 반영, 수정·새로고침·검색·백업·취소·모바일 화면, 섹션 편집 컨트롤 부재를 확인했습니다. JavaScript 오류 0건입니다.
- 이 결과는 모형 서버를 이용한 기능 검사이며 실제 사용자 데이터나 운영 Firebase 인증·동기화 성공을 새로 검증한 것은 아닙니다.

## damlog 데이터베이스로 연결 전환

사용자가 관리자 복사/검증 명령의 `verified: true` 결과를 확인한 후 정상 연결의 DB ID와 규칙 배포 설정을 `damlog`로 변경했습니다. 공유 프로젝트와 Authentication, 컬렉션 경로, 앱 IndexedDB 키는 유지했습니다. 기존 `damrok` DB는 삭제하지 않았습니다.

`damlog/tests/database-cutover.cjs`에서 모의 Firebase로 다음을 확인했습니다: 기존 기기 저장소와 복사된 서버 revision 보존, 정상 읽기/쓰기 전부 `damlog` 대상, 두 브라우저 수정 반영, 사용자 분리, 로그아웃 시 표시 자료 제거. 운영 Firebase 사용자 로그인과 서버 동기화를 직접 테스트한 결과는 아닙니다. 실제 계정에서 모든 기기의 이전 탭을 새로고침한 뒤 자료·파일 원본을 확인해야 합니다.
