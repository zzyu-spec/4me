## 추가 단계 · 하루결 계정 저장

변경: `cloud.js`, `app.js`, `data.js`, `style.css`, `sw.js`, 루트 `firestore.rules`/`firebase.json`, `docs/ACCOUNTS.md`, 계정 테스트.

- 기존 이메일 인증과 로그인 세션 재사용, UID별 IndexedDB, 기존 기기 기록 연결 확인
- 아르닛 전용 owner-only Firestore 스냅샷·사진 조각·이전 버전, 원본 해시 검증
- 실제 성공/저장 대기/오프라인/오류/충돌 표시, 자동 덮어쓰기 방지
- 같은 계정의 별도 기기 사진 복원, 로그아웃/계정 전환, 업로드 중 계정 변경 취소, 서버 거절 시 기기 기록 유지, 다운로드 중 편집 보호 검사 통과
- 테스트 SDK 기반 통합 검사이며 운영 Firestore 규칙 게시·사용자 실제 로그인 확인은 별도입니다.

## 남은 제약

- 공개 보드 공유는 제공하지 않습니다. 로그인 저장 코드는 구현했고 운영 적용에는 전용 Firestore 규칙 게시가 필요합니다.
- 상품 가격은 수동 입력입니다. 링크 메타데이터 자동 수집도 하지 않고 수동 이미지/제목 대체 흐름을 제공합니다.
- 외부 이미지 URL은 원본 서버의 정책을 따릅니다. 오프라인까지 보관할 이미지는 직접 업로드해야 합니다.
- 실제 사용자 브라우저의 비공개 데이터는 접근하거나 검사하지 않았습니다. 기존 원본은 남기고 브라우저에서 복사하도록 설계했고, 같은 스키마의 테스트 기록으로 검증했습니다.
- 기존 별도 Sites 배포는 변경하지 않습니다. 이 작업의 배포 대상은 사용자가 선택한 GitHub Pages입니다.

## 데이터베이스 분리 보완

사용자가 만든 `arnit` 데이터베이스를 SDK의 세 번째 인자로 명시합니다. 인증 프로젝트는 공유하고 Firestore 데이터베이스는 하루결 `(default)`와 분리합니다. 기기 기록은 그대로 유지하며 동기화 메타데이터만 데이터베이스별로 구분합니다. `taste-drawer/firestore.rules`와 `taste-drawer/firebase.json`을 별도로 제공하고, 루트 하루결 규칙·설정은 이번 보완에서 변경하지 않습니다.
